# 02 · 后端差异对比

## 一、总表

| 维度 | 原作者 v2.12（pc-agent） | 发起人 Web 版（webapp） | 合并结论 |
|---|---|---|---|
| 架构定位 | 家用 Windows PC 常驻 + 原生安卓 APP | 阿里云 ECS 常驻 + 浏览器/PWA | 云为核心，PC 作可选能力端 |
| 运行时 | Node 零依赖 8776 + Python（whisper/opencv/requests） | Node server.js（849 行）+ Python whisper | 两套 Node 同仓分模块，不强行合并运行时 |
| 部署 | 开机自启 + cloudflared + UDP 8779 发现 + ntfy 广播 | pm2 + cloudflared + HTTPS | 云为主入口；PC 走局域网/隧道 |
| 鉴权 | 固定 x-app-token（文件生成、烧进 APP） | 可选 CHAT_PIN（默认未开）+ 服务端 AI key | P1 统一为 token（APP/代理）+ PIN（Web 演示） |
| 存储 | 素材/<id>/ + 笔记/<id>/（JSON/MD/音频/图） | data/classes.json + data/sessions/<id>/ | P1 以他的 meta/status/items 为契约，扩展 AI 字段 |
| 上传 | 3MiB 分块 + md5 + 字节续传 + 同日同课合并 + 坏素材体检 | 30 秒 WebM 分段 + IndexedDB 补传 | P1 把他的分块续传/合并逻辑落到云后端 |
| 转写 | GPU large-v3（45 分钟课约 10~20 分钟） | 云端 CPU small/tiny（约 2.4 倍实时） | 默认云端；GPU 走 pc-agent 可选 |
| AI 成稿 | 无头 zcode 按《分析任务说明》还原；或 glm BYOK；或 template | ai_note.js + AI 助教四件套（glm-5.3-flash） | 统一 provider 抽象（GLM/DeepSeek/OpenAI 兼容/Claude） |
| API 面 | ~30 条（含学习通代理 6、修复、更新、诊断） | ~20 条（课表/EAMS/OCR/会话/AI 助教） | P1 合并 API 表，见 docs/04 |
| 学习通 | ✅ Python sidecar 扫码只读、反爬、5 分钟缓存 | ❌ 无 | v1 保留在 pc-agent，webapp 代理（已接） |
| 更新 | /api/version + APK + sha256 + 应用内更新 | PWA Service Worker | P4：壳内更新复用他的清单协议 |
| 推送 | ntfy（笔记完成 / 隧道地址） | 无 | P2 可选加 ntfy 或 Web Push |
| 课表 | 电脑端 timetable.json，手机缓存 | EAMS 账号/HTML/CSV/截图 OCR 多路导入 | 以 webapp 的导入能力为主 |
| 离线 | 手机缓存笔记/总纲/课表；电脑关机不能传 | SW 缓存 + 本地录音保活 | P3 壳内缓存 + 原生录音 |
| 多端 | 仅安卓原生，无 iOS | 安卓/iOS 浏览器/PWA | 以 webapp 为准，APP 壳补齐 |
| 安全 | token/凭据本机；旧版烧录 token 需轮换 | .env 密钥服务端；公网接口默认无口令 | 发布前统一脱敏 + 加口令 |

## 二、源码规模（v2.12）

- 安卓：29 个 .kt，约 9.4k 行（v2.5 为 22 个 / 6.7k 行）
- 电脑端：server.mjs 1393 行、pipeline 355、engines 281、transcribe.py 166、md2html 126、学习通 sidecar 882 + 客户端 791
- Web 版：server.js 849 行、public/app.js 约 3.5k 行、app.css 约 1.3k 行

## 三、结论

不是「两套后端缝在一起」，而是：**webapp 当大脑与门面，pc-agent 当双手（GPU/学习通/素材修复）**。数据契约以他的文件格式为真源（经过 67+ 篇真实笔记验证），接口面在云后端逐步对齐。
